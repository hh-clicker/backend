# Диагностика локальной установки

Нужен PowerShell 7. Скрипты работают только с loopback backend и Generation Agent.
Адреса и порт задаются через BackendUrl и AgentUrl. Никаких credentials или локальных
путей разработчика в скриптах нет. Параметр OutputDirectory задаёт каталог отчётов;
по умолчанию используется hh-clicker-diagnostics внутри системного временного каталога.
Отчёты не нужно коммитить или публиковать вместе с исходниками.

## Наблюдение

Из корня backend после запуска операции в UI:

```powershell
.\tools\watch-analysis-metrics.ps1 -Kind relevance
.\tools\watch-analysis-metrics.ps1 -Kind market
```

Скрипт только читает состояние и метрики, не запускает генерацию. При нескольких
операциях укажите -RunId '<UUID>'. Для benchmark тоже нужен явный RunId: контрольный
прогон не возвращается обычным active endpoint.

Доступны IntervalSeconds (по умолчанию 5), Samples (120), BackendUrl, AgentUrl и
OutputDirectory. Например, -OutputDirectory .\diagnostics сохраняет файлы рядом с
рабочим каталогом. JSONL содержит состояния, числовые счётчики, тайминги и UUID;
в нём нет текстов вакансий/резюме или сырых ответов CLI. Общие queue-счётчики относятся
ко всему агенту, summary фильтруется по выбранному запуску. Завершение определяется
также по родительскому состоянию, чтобы пауза между выдачей пачек не завершала наблюдение.

## Контрольная оценка без записи рейтингов

```powershell
.\tools\benchmark-relevance.ps1 -ResumeId '<UUID резюме>'
```

При одном резюме ResumeId можно опустить. Скрипт выбирает его сохранённые вакансии,
создаёт POST /api/v1/vacancies/relevance/parallel с benchmark=true и ждёт результат.
Уже оценённые карточки тоже участвуют. Рейтинги не записываются, уведомления не отправляются,
но Codex вызывается по-настоящему: расходуется лимит, задания агента сохраняются на диске.
Новых обращений к HH нет. Контрольный запуск занимает резерв резюме до завершения исполнителей.

JSON-отчёт содержит длительность, прогресс, пик runningRelevance, параметры памяти и
сравнение хеша прежних рейтингов. Пик измеряется периодически и может быть занижен.
Параллельное ручное изменение/удаление карточек может изменить сравнение независимо от benchmark.
Если ожидание прервано или превысило 30 минут, скрипт пытается отменить дальнейшую
обработку родителя. Уже отправленные задания агента могут продолжить работу.

## Диагностические endpoints

- Generation Agent: GET /health, GET /metrics?runId=<UUID>.
- Backend relevance: GET /api/v1/vacancies/relevance/parallel/<UUID>.
- Backend market: GET /api/v1/market-analyses/<UUID>.

Чтение этих endpoints не вызывает модель. Метрики результата агента не доказывают
применение результата в БД: сохранённый прогресс проверяется по backend.

Инструменты доступны из исходников; каталог tools не включается в installer или backend image.
